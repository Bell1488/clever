# Клевер — готовая сборка сайта

Здесь самостоятельная версия сайта с сервером заявок. Нужен Node.js 22.13 или новее. Сборка уже готова: npm, Docker и установка зависимостей для запуска не нужны.

## Запуск для проверки

1. Скопируйте `env.example` в `.env`.
2. В `.env` задайте уникальный `ADMIN_PASSWORD` от 16 символов.
3. Выполните в этой папке:

```bash
node --env-file=.env server.mjs
```

По умолчанию сайт доступен на `http://127.0.0.1:3000` и остаётся в режиме проверки. На сервере настройте HTTPS через Nginx/Caddy и проксирование на этот локальный порт. Пример Nginx есть в общем архиве `docs/nginx.conf`.

## Где заявки

После подтверждения формы заявка записывается в `data/requests.ndjson` (или папку `DATA_DIR`). Папка данных находится вне public и не раздаётся посетителям. Смотрите заявки по адресу `/admin`, логин `admin`, пароль из `ADMIN_PASSWORD`. JSON для внутреннего использования — `/api/admin/leads` с той же HTTP Basic авторизацией. Используйте HTTPS. Веб-панель показывает последние 500 заявок; исходный журнал хранит все. Настройте регулярную резервную копию и удаление по принятому сроку хранения.

Уведомления в Telegram отправляются через SOCKS5h после настройки TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID и TELEGRAM_PROXY_URL. Инструкция — docs/TELEGRAM.md в корне архива. Без этих настроек заявка сохраняется со статусом ожидания; интерфейс не сообщает об успешной доставке в Telegram. Прямые ссылки мессенджеров настраиваются отдельно.

## Перед рекламой

- Укажите окончательный `SITE_URL` с HTTPS, номер `METRIKA_ID`, хотя бы один публичный канал связи (`TELEGRAM_URL`, `MAX_URL`, телефон или email), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и рабочий `TELEGRAM_PROXY_URL` в формате `socks5h://...`. Заполните отдельный длинный `ADMIN_PASSWORD`.
- Создайте цели в своём счётчике по `docs/METRIKA.md` из корня архива и привяжите его к Директу.
- Платёжный калькулятор показывает курс 12.79 RUB/CNY. Перед запуском подтвердите, что это публичная ставка, и обновляйте её в `source/lib/calculators.ts`; тарифы и сроки карго остаются предварительными, их нужно сверить с фактическими условиями.
- Portable-сервер автоматически удаляет заявки старше 90 дней и компактизирует журнал при старте/раз в сутки. D1-вариант включает ежедневную очистку Worker по cron в 03:00 UTC; после развёртывания проверьте, что cron trigger активен. Храните `DATA_DIR` вне публичной директории, настройте зашифрованный backup, ограничьте доступ к нему и проверяйте восстановление.
- Для рекламной публикации проверьте документы и фактическую схему обработки данных, включая хостинг, доступы и передачу уведомлений в Telegram; при необходимости согласуйте юридические тексты со специалистом.
- `PUBLIC_LAUNCH=true` лишь разрешает публикацию при наличии HTTPS-домена, счётчика, рабочего контакта и настроенной доставки заявок. Проверка конфигурации всё равно оставит `noindex`, если обязательный параметр отсутствует. Приватную исходную публикацию это не делает публичной.
- Отправьте тестовую заявку и проверьте её в `/admin`, а событие `lead_success` — в вашем счётчике.

Маршруты главной, карго, блога, статей и документов включены. Страницы уже содержат HTML-текст для индексирования; скрипты добавляют интерактивность. При `PUBLIC_LAUNCH=false` сервер отдаёт noindex и запрещающий robots.txt. После включения запуска robots.txt разрешает основные страницы и исключает служебные. Sitemap доступен при заполненном SITE_URL.

Не размещайте `.env`, серверный код и каталог данных внутри чужого public_html. Для готовой сборки нужен Node.js-хостинг/VPS, а не только статический или PHP-хостинг.
