# Яндекс Метрика и Директ — Клевер

События встроены на всех страницах. Сам счётчик и цели в вашем кабинете не создавались: номер счётчика и доступ к кабинету не переданы. Публикация остаётся приватной. В режиме проверки внешняя Метрика не загружается, чтобы не смешивать тесты с рекламными визитами.

## Подключение

1. Создайте счётчик для своего окончательного домена в Яндекс Метрике.
2. Для самостоятельной сборки задайте `METRIKA_ID` в файле `.env`. Для текущей приватной версии этот параметр задаётся в настройках развёртывания.
3. Создайте цели типа «Целевое событие» (JavaScript) с идентификаторами из таблицы ниже. Идентификаторы должны совпадать посимвольно.
4. Укажите рабочие `TELEGRAM_URL`, `MAX_URL`, `CONTACT_PHONE` и `CONTACT_EMAIL`. Без ссылок кнопки мессенджеров честно открывают форму и вызывают отдельные события; они не имитируют прямой переход.
5. После проверки домена, контактов, ставки 12.79 RUB/CNY, тарифов карго, документов и обработки заявок задайте `PUBLIC_LAUNCH=true`. Сборка оставит preview/noindex, пока не настроены HTTPS-домен, счётчик, публичный контакт и Telegram-доставка (бот, chat ID и SOCKS5h-прокси для portable-сервера). Разрешение владельца на публичный доступ к текущей приватной публикации требуется отдельно.
6. Счётчик загружается только после отдельного разрешения посетителя. Отказ от аналитики не блокирует формы.
7. В Директе привяжите этот же счётчик. Главная цель для оптимизации — `lead_success` (или один нужный сегмент: `payment_lead_success` / `cargo_lead_success`). Не складывайте общую цель с её сегментами: это одни и те же обращения.

## Источники и приватность

UTM-метки и `yclid` сохраняются на время вкладки и прикладываются к заявке. Данные первой сохранённой заявки не меняются при последующих переходах. В параметры целей не отправляются имя, номер, username, текст комментария, реквизиты или параметры суммы. Вебвизор выключен. Форма дополнительно помечена `ym-disable-keys`.

## Проверка

Откройте `/?analytics_debug=1`. Внизу страницы появится панель проверки целей. После действий локальный журнал также доступен в `sessionStorage.klever_goal_debug`; там только идентификаторы и безопасные категории. В приватном режиме внешние запросы в Метрику не идут. Для проверки доставки в настоящий счётчик используйте подключённый счётчик, публично доступную боевую копию и отладку Метрики; возможны блокировщики и отказ от аналитики.

Проверочный сценарий: открыть форму → изменить поле → отправить валидные тестовые данные → дождаться номера заявки. В журнале должна быть ровно одна `lead_success`. Ошибка формы или сервера не должна давать успешную конверсию.
